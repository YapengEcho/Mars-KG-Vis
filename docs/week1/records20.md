## 1. 三个前提

1. 这 20 条**全部是真实编目记录**，编号、类型、坐标、面积都直接取自交接包，没有补值、没有模拟。
2. 它们**现在还不能当 APP 可发布目录**：纬度约定未核准、`imageUrl` 未接入、`summary` 无出处文本。`records20.json` 里每条都带 `coordinateStatus: latitude_convention_pending_verification`。
3. 样例是按“每类 5 条”抽的，**没有按模型分数筛选**，也没有挑“好看的图”。

## 3. 与 APP 契约的差异

| 契约字段 | 样例中的值 | 说明 |
|---|---|---|
| `name` | `滑坡 493` 这类回填名 | 原表 `name` 全为空，按契约规则回填；有正式地名后替换 |
| `summary` | 空字符串 | 原表 `desc` 全为空，不编造 |
| `imageUrl` | `null` | 本地 `03_images/...` 不是可访问 URL |
| `source` | 论文题名 + DOI | 可追溯；页面展示时需带“编目来源”标签 |
| `isDemo` | `false` | 真实记录 |
| `handoff` | 额外块 | **不属于** APP 契约，导出到 APP 前必须剥离 |

剥离命令（导出到本地目录时）：

```bash
python scripts/export_catalog.py --input <源 JSON 数组> --output mobile/public/data/catalog.local.json \
  --source-title "火星全球滑坡编目（张乐飞等）" --coordinate-system planetocentric
```

注意 `export_catalog.py` 只接受“源 JSON 数组”这一种输入，`records20.json` 是契约形状、不是源数组；真正导出全量目录要用 `mars_landslides.json`。

## 4. 已知瑕疵（不影响样例成立）

- `ls_0690`、`ls_0687`、`ls_0688`、`ls_0686` 等低纬度记录，SHP 里的度分秒文本丢了负号（度为 0 时），样例用的是数值字段，因此不受影响；详见数据字典第 5 节。
- 样例覆盖 2971 条目录的 20 条，不构成统计样本，不能用于估计类别比例或空间分布。
