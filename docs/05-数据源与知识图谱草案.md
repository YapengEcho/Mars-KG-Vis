# 数据源与知识图谱草案

滕佳杰主笔落地，全组按这里的 ID 和对齐字段写代码。数据源若有变，先改本文再改脚本。

## 主数据（必须有）

优先使用 **Mars Landslides / 火星滑坡编目** 类公开表（HiRISE / MRO 相关文献附带的编目，或 NASA PDS / USGS 发布的滑坡位置表）。目标不是爬尽全网，而是拿到一张能讲清楚的表：

最少列：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定主键，入库前生成 `ls_xxxx` |
| `lat` `lon` | 十进制度，统一到东经/北纬为正 |
| `type` | 枚举：`slump` / `fall` / `flow` / `slide` / `unknown`（以实际编目为准，冻结后不要每周改名） |
| `length_m` `width_m` | 可空 |
| `mission` | 探测任务，如 MRO、Viking |
| `source_url` | 原始记录链接 |
| `description` | 英文或中文短描述，给 RAG |

第 1 周允许只有 50 条样本进 MySQL。全量下载脚本要可重复跑。

## 爬虫（课程基本项）

不要用 Scrapy 铺开。用 `requests` 打一个**真实存在的列表或元数据页**（例如 PDS 检索页、编目 HTML 表、DOI 落地页），解析出若干字段或 PDF 链接，写入 `data/raw/crawl/`。

报告里写：爬了哪个 URL、间隔多少秒、遵守 robots、失败如何重试。禁止把「手动下载 CSV」包装成爬虫；手动下载可以是主数据，爬虫是另外一条脚本。

## 辅数据（给 RAG 和图谱，不是主表）

- 类型说明：从综述里摘 4–6 段中文（自己写释义也可以，注明来源）
- 任务百科：MRO / HiRISE / CTX 各一段
- 可选：2–3 篇开放获取论文摘要，不要整本 PDF 塞进 Git

## 清洗规则

- 去空坐标、去重复 id
- 经纬度范围检查（火星坐标，不要用地球行政区去筛）
- 类型映射到冻结枚举，无法映射则 `unknown`
- 单位统一到米、度
- 产出两份：`landslides.csv`（MySQL）和 `triples.csv`（Neo4j）

## 图谱

### 实体

- `Landslide {id, name, lat, lon}`
- `LandslideType {name}`
- `Region {name}`（按纬度带或命名区，粗即可）
- `Mission {name}`
- `Feature {name}`（如 crater wall, polar cap）
- `Paper {doi, title}`（可空）

### 关系

- `(Landslide)-[:IS_TYPE]->(LandslideType)`
- `(Landslide)-[:LOCATED_IN]->(Region)`
- `(Landslide)-[:OBSERVED_BY]->(Mission)`
- `(Landslide)-[:HAS_FEATURE]->(Feature)`
- `(Landslide)-[:SIMILAR_TO]->(Landslide)`（可由特征距离离线生成）
- `(Landslide)-[:MENTIONED_IN]->(Paper)`

### 演示查询

「某种类型的滑坡出现在哪些区域」「某任务观测到哪些类型」「和这条最像的 5 条」。这些必须在 Neo4j Browser 里也能跑，视频可以切 5 秒。

## fallback

`data/processed/graph_fallback.json` 放 1 个中心节点 + 约 20 个邻节点，保证 Neo4j 挂了大屏仍能画图。格式与 `/api/graph/subgraph/` 相同。

## 法律与引用

公开科学数据要在报告里列来源 URL 和引用格式。爬虫不对需登录的商业站点硬爬。样本数据进 Git 前去掉无法再分发的全文 PDF。
