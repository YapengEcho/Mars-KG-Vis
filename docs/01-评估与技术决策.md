# 评估与技术决策

对照课程 PPT《Python程序设计-项目要求-2024》（温泉，成都理工大学）和现有 [分工.md](../分工.md) 做的立项判断。结论已经写进仓库，后续改栈要全组同意。

## 课程在考什么

基本项（没有就不及格）：

1. 互联网爬取 **或** 传感器采集
2. 数据处理 / 清洗 / 挖掘
3. 数据库存储
4. Web **或** 移动 **或** 桌面可视化，且题目原文要求最后实现对数据的 **预测、推荐**

加分项（报告里必须写清楚怎么做的）：

- 主流技术：Vue、Django、Redis、AI
- 国产框架
- Git 仓库
- 代码优化
- AI 协助开发
- AI 功能模块

交付：源代码 + GitHub 链接、2 分钟视频、项目报告（需求分析、功能模块详解、加分项说明）。组员 1–5 人，超过 5 人减分。我们 4 人，合规。

老师给的分工范例就是「前后端分离，Vue、Django、MySQL」，组长管团队 + 后端库表。我们的交稿格式已按这一页对齐。

## 选题判断

自拟题「火星滑坡分类知识图谱与可视化」是合适的：

- 有公开科学数据，能做出真实的采集/清洗，不是纯玩具爬虫。
- 分类本身就是预测问题；同类滑坡检索就是推荐。
- 图谱和 RAG 能把「AI 功能模块」做扎实，演示差异明显。
- 和地球科学、遥感、知识工程有课程融合感。

风险：数据量可能只有几百到几千条。这不是问题——课程看的是链路和可视化，不是论文精度。不要把时间花在刷准确率上。

## 原分工：哪里是对的

| 点 | 为什么对 |
| --- | --- |
| 4 人按后端 / 数据 / 前端 / AI 切开 | 和老师范例同构，接口边界清楚 |
| 组长兼 Django + Git | 范例就是这样，避免「组长只开会」 |

| 前端扛演示 | 2 分钟视频几乎全是画面 |
| RAG 作为加分模块 | 对应「AI 功能模块」 |

## 原分工：必须改的 6 件事

1. **预测/推荐缺失。** 原方案把周璇写成纯 RAG + 测试。课程题目和评分第 2 条都要求预测、推荐。现已明确：sklearn 分类 + 相似滑坡推荐是周璇的主路径，RAG 是加分。
2. **Django / Flask 摇摆。** 老师加分示例写的是 Django。4 人课设选 Django + DRF，不要 FastAPI，不要 Flask。
3. **Redis 双负责人。** 原方案组长和周璇都写了 Redis。归后端，周璇只提「哪些接口慢」。
4. **栈过重。** Scrapy、Milvus、原生移动 App、完整 JWT 用户系统，课设周期里做不完。全部降级或砍掉（见下表）。
5. **「多终端」被理解成两套产品。** 老师允许 Web **或** 移动 **或** 桌面。正确做法：一套 Vue，PC 大屏 + 移动端响应式。手势只在 PC 开摄像头。
6. **数据源太散。** 「NASA、USGS、论文、Kaggle」四路并行，4 人组会在找数上耗死。主数据锁定一个滑坡编目，论文只当 RAG 语料。

## 技术栈冻结

| 用途 | 用 | 不用 | 原因 |
| --- | --- | --- | --- |
| 后端 | Django 4.2 + DRF | Flask / FastAPI | 课程加分点点名 Django |
| 前端 | Vue 3 + Vite + Element Plus | React / 原生 App | 与范例一致，生态熟 |
| 地图 | Leaflet + 火星底图瓦片 | 一上来 Cesium | 课设够用，Cesium 学习成本高 |
| 3D | Three.js 仅首页星球 | 全站 3D | 演示开场用，分析页 2D |
| 图表 | ECharts | D3 从零 | 大屏快 |
| 业务库 | MySQL 8 | PostgreSQL / SQLite 作为主库 | 与范例一致 |
| 图库 | Neo4j Community Docker | 纯 JSON 假装图谱 | 要能打开 Neo4j Browser |
| 向量库 | Chroma 本地目录 | Milvus | 千条文档不够 Milvus 登场 |
| LLM | 通义千问（DashScope） | 默认 OpenAI | 「国产」加分；国内好申请 |
| RAG 框架 | LangChain | LlamaIndex 双栈 | 只留一个 |
| 预测 | scikit-learn | PyTorch 主模型 | 样本量小，sklearn 能讲清 |
| 缓存 | Redis | 进程内缓存冒充 | 加分项，Docker 起 |
| 语音 | Web Speech API | 一上来讯飞商用 | 零密钥先跑通；Chrome 即可 |
| 手势 | MediaPipe Hands | 全身姿态 / 自定义训练 | PC 演示 2–3 个手势够 |
| 爬虫 | requests + 一个列表页 | Scrapy 整站 | 课程要「有爬取」，不是爬虫课 |
| 认证 | 先不做登录 | JWT 全套 | 演示无用户体系也能跑 |
| 部署 | 本机 Docker Compose | 云服务器必选项 | 视频录本机即可 |

## 范围：做 / 冲刺 / 不做

**必须做（演示不能缺）**

- 公开数据接入 + 至少一条真实 HTTP 爬取
- 清洗表：缺失、异常、坐标、类型枚举
- MySQL 存滑坡记录；Neo4j 存类型/位置/特征/任务关系
- PC 大屏：分布、统计、图谱、详情
- 移动端同一站点可翻看列表和问答
- 类型预测（输入特征 → 类型）
- 相似推荐（一条滑坡 → 若干条）
- RAG 问答（中文，3–5 个固定问题要答得像样）
- 语音指令 ≥ 5 条

**冲刺（有时间再做，没有也不挡提交）**

- 手势缩放/旋转
- Redis 缓存命中演示
- 讯飞语音降级
- 简单登录
- 图谱 3D 力导向

**明确不做**

- iOS / Android / 小程序
- 实时卫星流、传感器硬件
- 自己训练大模型
- 多用户权限、后台 CMS
- 把 Kaggle 地球滑坡当火星数据充数（报告里会露馅）

## 加分项怎么「看得见」

老师看报告和视频，不看你本地有没有装包。每项都要能指出来：

| 加分 | 落点 |
| --- | --- |
| Vue / Django / Redis / AI | 技术栈页 + 运行截图 |
| 国产框架 | 通义千问调用代码 + 控制台申请截图 |
| Git | GitHub 地址、分支、PR 记录 |
| 代码优化 | 分页、Redis 缓存、N+1 查询说明（一段即可） |
| AI 协助开发 | 报告专节：用了哪些工具、改了什么、人如何验收 |
| AI 功能模块 | 预测 + 推荐 + RAG，视频里各给 10–15 秒 |

## 最大风险

1. **数据源链断裂。** 编目地址变更或下载要注册。对策：主数据进仓库的 `data/raw/sample/`（脱敏小样本），全量放网盘，脚本可重复跑。
2. **Neo4j 演示现场起不来。** 对策：`/api/graph/subgraph` 在图库不可用时读 `data/processed/graph_fallback.json`。
3. **大模型无密钥或欠费。** 对策：RAG 对 5 个标准问题准备本地 FAQ 回退。
4. **前端一人过载。** 对策：手势可砍；大屏先 3 个图表 + 地图，再加动画。
5. **接口对不上。** 对策：第 1 周冻结 URL 和字段，见 [03-里程碑与接口约定.md](03-里程碑与接口约定.md)。
